# Roadmap

Use [readiness](docs/readiness.md) for evidence and open issues. The October
[review](docs/project-review-2026-10-03.md),
[remediation](docs/remediation-2026-10-03.md), and
[follow-up](docs/project-review-2026-10-05.md) preserve the original findings
and enhancement registers.

## Current local foundation

The repository contains a theme-free Hugo site, module contracts and a local
workshop, three build profiles, a Storyscape brand kit with responsive artwork,
polished client-facing copy (with public AI-generation notices removed), and
shared inquiry rules. The optional Cloudflare inbox and the private Lantern
Bay session-copy command are in place. The exemplar and remote static builds
have focused local evidence; see readiness for the limits.

## Next: verify and make the example easy to use

1. Make a private Lantern Bay copy, read it through, and playtest it. Use the
   blank observation sheet to record where a participant or facilitator gets
   stuck or has to repeat work.
2. Before relying on the website or intake, address the relevant open source
   issues in [readiness](docs/readiness.md#open-source-issues), then use the pinned
   toolchain and a focused browser and runtime pass for the chosen profile.
3. If publishing or accepting inquiries is the goal, decide the release scope
   and confirm the necessary rights, contact, host, and operating details first.

## Then: deepen reusable working materials

Use the October reviews as idea lists. Consider a reviewable handoff from an
inquiry to a private scope only if moving information by hand becomes a burden.
Extend the pack with more scenes, handout formats, or search when actual use
shows a need. Keep sample and private session data separate. Add a composition
exporter if choosing modules still takes too much input.

## Conditional integrations

Scheduling, payment, mailing lists, analytics, and VTT exports require an explicit
use case, selected provider, rights review where relevant, and verified failure
handling. They are not necessary for the personal exemplar to be useful. Trust
modules need approved real quotations; a booking scaffold does not imply connected
availability. Automatic retention remains off until the owner approves a policy
and a safe, reviewable implementation.
